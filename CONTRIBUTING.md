# Contributing to Academic Colombia

Academic Colombia is public and reusable, but `main` is treated as a protected canonical branch.

## Allowed contribution paths

Contributors should:

1. Fork the repository or create a feature branch when they have write access.
2. Make changes outside `main`.
3. Add or update tests when behavior changes.
4. Open a pull request against `main`.
5. Explain source authority, institutional impact and regression risk.

Direct commits to `main` are not part of the project workflow.

## Branch naming

Recommended prefixes:

- `feat/` new capability;
- `fix/` correction;
- `docs/` documentation;
- `test/` regression/acceptance coverage;
- `chore/` governance or maintenance.

## Pull request expectations

A PR should include:

- objective;
- files/capabilities affected;
- source or authority used for normative changes;
- tests performed;
- compatibility impact for UNAD/SENA/APA/general academic use;
- whether external references were consumed.

## Academic safety

Do not commit:

- private student submissions;
- personal identifiers or grades;
- confidential institutional documents;
- fabricated citations or metadata;
- copyrighted manuals copied extensively.

Use anonymized regression cases and copyright-safe summaries.

## External references

Third-party repositories and guides may inform design only according to `external-references/REGISTRY.md` and `skills/external-reference-resolver/SKILL.md`.
