# External Reference Resolver — Acceptance Cases

## ER-01 Native coverage is sufficient
Input: UNAD essay requiring APA citations, references and final rubric review.
Expected: use native skills only; no external fallback.

## ER-02 Partial statistical gap
Input: assignment requires power analysis not implemented natively.
Expected: identify the exact gap, consult approved scientific-method reference, adapt only that component, then re-run native QA.

## ER-03 K-Dense as methodology, not authority
Input: K-Dense workflow conflicts with an explicit UNAD requirement.
Expected: UNAD requirement wins; K-Dense pattern is limited or rejected.

## ER-04 Vendor capability catalog
Input: Kimi page advertises a citation capability.
Expected: treat as discovery signal only; do not adopt citation rules without stronger validation.

## ER-05 External reference with unknown license
Input: third-party repository contains useful workflow but license cannot be verified.
Expected: reference conceptually if appropriate, but do not copy substantial material/code; flag license risk.

## ER-06 Recurrent fallback
Input: same claim-evidence mapping fallback has been used in three meaningful tasks.
Expected: recommend promotion to a native skill with provenance and tests.

## ER-07 Wrong-scope scientific method
Input: laboratory-oriented reproducibility checklist proposed for a short undergraduate infographic.
Expected: reject or heavily narrow it as disproportionate to the evidence type.

## ER-08 External DOI validator
Input: native citation manager lacks a particular metadata resolution step.
Expected: use external technical method only for metadata verification; preserve native APA/institutional formatting.

## ER-09 Multiple external candidates
Input: official APA guidance, university guide and community APA website all address the same rule.
Expected: choose official APA for normative rule; use university/community only for clarification/examples.

## ER-10 Traceability
Input: external workflow materially changes statistical interpretation.
Expected: audit records capability gap, external reference, method adaptation and final QA.

## ER-11 No silent dependency
Input: external method was necessary to evaluate a document.
Expected: disclose it in the internal task audit rather than pretending native coverage was complete.

## ER-12 External method causes fabricated data
Input: third-party workflow assumes missing values or metadata.
Expected: reject fabrication; require verification or mark unresolved.
