## What the corpus says about Skill behavior

The strongest evidence is not that every artifact passes. It is that different Skills identify different failure classes without collapsing them into one generic score:

- `academic-document-auditor` can PASS layout while `academic-evidence-mapper` fails traceability;
- `academic-source-evaluator` can accept an official current fact while `academic-citation-manager` still reports missing inline support;
- `academic-critical-review` catches non-comparable periods even when the table is visually correct;
- `academic-final-review` can return NOT READY for a submitted artifact when evidence/method gates remain unresolved;
- `academic-statistical-analysis` is not routed merely because an assignment contains numbers.

This is the intended architecture.

## v1.0 minimum release gates

Academic Colombia may proceed to v1.0 when all of the following are true:

1. core + Skill Contract remain stable through the final pre-release PR;
2. declarative repository validation remains green on normal PRs;
3. README, Skills Directory, installation/distribution docs and license scope are consistent;
4. no unresolved critical governance or evidence-integrity issue exists;
5. empirical registry clearly distinguishes executed cases from fixtures;
6. platform runtime validation is either completed for platforms publicly advertised as runtime-validated, or explicitly marked pending/not claimed;
7. a release/compatibility policy defines what SemVer means for declarative behavior.

## What does NOT need to block v1.0

The following may continue after v1.0:
- additional real cases;
- more universities;
- exhaustive XLSX/PPTX/video coverage;
- more few-shot examples;
- additional external references;
- telemetry;
- RAG/runtime infrastructure;
- new platform adapters.

## Academic integrity Skill decision

Current evidence still does **not** justify a separate `academic-integrity-review` Skill before v1.0.

Existing capabilities already detect:
- weak/obsolete sources;
- unsupported claims;
- citation/reference mismatch;
- methodological comparison errors;
- overclaiming;
- current-fact freshness requirements;
- AI/figure attribution needs.

The expanded corpus strengthens the case for composition of existing Skills rather than adding a redundant general-purpose integrity Skill.

Functions intended to evade AI/plagiarism detectors remain explicitly out of scope.

## Current recommendation

The framework remains in **v1.0 release preparation**, not feature development.

The empirical gap is now materially smaller across both UNAD and SENA. Remaining release work is:
- release and compatibility policy;
- final repository/documentation audit;
- tag/release preparation;
- runtime acceptance when the actual GPT/Gem instances are available.
