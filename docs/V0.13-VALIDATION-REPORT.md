# v0.13 Validation Report

## Scope

v0.13 adds automated consistency checks for the **declarative repository**. It does not attempt to execute or grade the academic reasoning described by the Skills.

## Added validation

`python scripts/validate_repo.py` checks:

1. required canonical files;
2. SemVer-like `VERSION`;
3. first `CHANGELOG.md` release equals `VERSION`;
4. every directory in `skills/` contains `SKILL.md`;
5. each Skill's first heading matches its directory name;
6. Skill Contract v1 / `critical_gate` markers;
7. distribution manifest and canonical skill inventory agree;
8. relative Markdown links resolve inside the repository;
9. external-reference registry defines canonical A–E classes;
10. Skill packager exists and generated `dist/` is ignored.

The GitHub workflow additionally runs `scripts/package_skills.py` to ensure distribution packages can be generated from the canonical Skills.

## Acceptance specification

`tests/REPOSITORY_VALIDATION_CASES.md` defines 20 positive/negative cases.

## Important boundary

A green structural check does **not** prove that an academic rule, source interpretation, citation decision or artifact judgment is correct.

Those behaviors remain governed by:

- academic acceptance/regression cases;
- adversarial cases;
- end-to-end artifact validation;
- platform runtime acceptance;
- human review where required.

## Findings from the first real CI run

The first PR run correctly failed and surfaced two issues:

1. `academic-evidence-mapper` used the heading `Contrato común` instead of the canonical `Skill Contract v1` marker. Its behavior already referenced the correct contract, so this was normalized without changing academic logic.
2. The manifest parser interpreted the documentation placeholder `skills/<name>/SKILL.md` as a real Skill. The validator was corrected to ignore explicit placeholder names.

These findings demonstrate why the validation layer is useful: it can find both repository inconsistencies and false-positive assumptions in the validator itself.
